# share2
原さんへの委託の件ですが、Code-as-Policyに関連して、何かやってみたいことはありますか？

個人的には、原さんが一番モチベーションを持って取り組めるテーマの方が、良い成果につながると思っています。そのため、興味のあるテーマや挑戦してみたいことがあれば、できるだけそれに合わせて委託内容を検討したいと考えています。

こちらとしては、IROS 2027への論文投稿を目指せるような研究要素があると嬉しいです。

現在、我々が取り組んでいるのは、Code-as-Policyを実際の製造現場・工場で運用できるレベルまで発展させることです。
関連研究としては、CaP-XやGraph-as-Policyなどを意識しています。

すでに取り組んでいる内容としては、以下のようなものがあります。

マルチモーダルな情報を活用したタスク生成
指示文だけでなく、作業動画、作業手順書、ロボットシステムの設計図、ソフトウェアなどを1つのフォルダに格納し、エージェントが必要な情報を自律的に探索・理解して、ロボットの動作プログラムを生成する。

スキルの自動生成・更新
事前定義されたスキルを組み合わせるだけでなく、必要に応じてエージェントが新しいスキルを生成したり、既存スキルを改善したりする。

熟練者のノウハウの蓄積・活用
スキルの生成・更新と並行して、現場の熟練者とのチャットによる対話から、作業のコツや判断基準、暗黙知を引き出して蓄積する。蓄積したノウハウをエージェントが参照し、動作プログラムの生成や改善に活用する。

実際の製造現場での実機検証
シミュレーション中心のCaP-Xなどに対して、実際の製造工程を題材に、実機での動作検証まで行う。

これだけだとイメージが湧きにくいと思うので、研究テーマの例をいくつか挙げてみます。

Code-as-Policyから呼び出せる高性能VLAモデルの開発
エージェントが選択するスキルの1つとして、安全性・安定性・成功率・実行速度に優れたVLAモデルを開発する。

省計算資源で動作するローカルAIエージェントの開発
クラウドに依存せず、VRAMの少ないローカルGPU環境でも十分な性能を発揮できるCode-as-Policyの仕組みを実現する。

ロボット動作プログラムの自動検証・修正技術
エージェントが生成したコードについて、シミュレーションや安全性評価を通じて問題点を検出し、実機で実行する前に自動修正する仕組みを開発する。

実機の失敗経験を活用したスキルの自動改善技術
ロボットの実行結果や失敗時の映像・センサ情報をもとに、エージェントが失敗原因を分析し、スキルや動作プログラムを自律的に改善する仕組みを開発する。

異なるロボット間でのスキル転移・汎用化技術
あるロボット向けに生成したスキルを、別のロボットや異なる作業環境でも再利用できるようにする技術を開発する。

製造現場の精密作業に特化したVLAモデルの開発
微小部品の把持・挿入・組立など、位置精度や繊細な操作が求められる作業に特化したVLAモデルを開発する。特に、視覚情報だけでは判断が難しい接触状態や力加減を考慮した動作生成を目指す。

力覚・触覚情報を活用したスキル・ノウハウ・モデルの高度化
熟練者が感覚的に調整している押し付け力や接触状態、力の抜き方などを、スキルやノウハウとして表現・蓄積する。さらに、力覚・触覚情報をVLAモデルにも組み込み、接触を伴う作業を安定して実行できる仕組みを開発する。
もちろん、これらはあくまで例なので、必ずしもこの中から選んでいただく必要はありません。
